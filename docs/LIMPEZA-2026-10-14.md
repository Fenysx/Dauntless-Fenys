# Limpeza do launcher novo — 14/10/2026

Esta limpeza foi feita para que o **Dauntless Launcher Ultimate** ofereça apenas os fluxos escolhidos para a nova versão: **Servidor local**, **Servidores da comunidade**, **Conta Google/Supabase**, hospedagem LAN/HTTPS e recuperação segura do personagem antigo.

## Removido do código ativo

| Remoção | Motivo |
|---|---|
| Assistente Tailscale, instalação, modo em segundo plano e compartilhamento | O jogador não deve depender de VPN; a comunidade nova usa Google e host público HTTPS |
| `src/fenys-tailscale.js` e teste específico | Não há mais opção de gerenciar Tailscale pelo launcher |
| Cadastro clássico com convite e chave manual | Jogadores novos entram pelo Google; manter dois fluxos de criação causava confusão e risco de contas duplicadas |
| Conexão antiga `FENYS1` por código manual e painel de IP | A escolha atual usa servidor local ou catálogo de comunidade e convites Google |
| `src/fenys-connection-code.js`, `src/fenys-server-setup.js` e teste de integração clássico | Implementavam a configuração e o ingresso por Tailscale retirados do produto |
| Painel antigo de PC central/rede global (interface e IPC de ativação) | Substituído pelo modelo em que o Supabase associa snapshots ao login Google |
| Painel manual de endereço do servidor | Elimina mais um caminho para configurar um destino incompatível com a conta Google |
| Opções para criar VIP e convites VIP | Não fazem parte da versão simplificada; nova UI envia convites comuns, sem cobrança |
| Scripts/documentação de preset pessoal do personagem Fenysx | São operações particulares do dono e não pertencem à distribuição do launcher |

Os arquivos removidos continuam recuperáveis no **histórico deste repositório privado**. Excluí-los de uma revisão **não** remove seus conteúdos dos commits anteriores.

## O que precisa permanecer

- **Recuperação de conta antiga e leitura de chaves locais:** necessária para provar que o personagem existente pertence à conta que será vinculada ao Google. Não apague `account.key` nem o SQLite do servidor original.
- **Bibliotecas `fenys-host-setup.js`, `fenys-private-listener.js` e protocolos de rede:** ainda são usadas pelo overlay Google e instalações existentes. Não são o instalador do Tailscale removido.
- **Leitores `fenys-cloud-*`, `fenys-direct-global.js` e compatibilidade antiga de Supabase:** ainda são referenciados na inicialização e execução de hosts legados para preservar dados. A nova UI não oferece criação ou ativação desse modelo; futuras remoções dependem de migração/backup comprovados.
- **Backend de permissões VIP já cadastradas:** preservado para não revogar silenciosamente acessos existentes. A UI nova não cria novos VIPs e o modelo não é apresentado como cobrança.
- **Metagame, DeployServer, Google Auth, Edge Functions e save sincronizado:** são parte da nova versão e não podem ser descartados.

## Validação e limites

O código foi revisado para assegurar IDs HTML únicos, fechamento de tags, handlers dos botões presentes, canais IPC expostos com receptores correspondentes e sintaxe JavaScript dos arquivos alterados. O teste histórico com número fixo de botões foi ajustado à interface simplificada.

Isso **não confirma** que uma caçada foi executada ou que o personagem foi sincronizado na máquina do dono. Os workflows do GitHub Actions falham antes de iniciar steps (issue #25). Uma compilação/instalação real só pode ser considerada validada quando esses testes forem executados e os cenários de Google/partida passarem.

## Antes de abrir o código ao público

**Não transforme diretamente este repositório privado em público** se quiser esconder os scripts pessoais antigos: eles continuarão visíveis no histórico de commits. Crie uma cópia pública de histórico novo, sem presets privados, `.env`, chaves nem dados de personagens, e revise os pacotes/release antes de publicar.
